DJ OPERATOR GUIDE

Run Cue the Crowd with confidence.

This guide is the complete operating manual for the host side of Cue the Crowd. Start with the first-event walkthrough, then use the feature reference whenever you need to know what a control does, when to use it, and why it matters.

START HERE

Your first event, from login to final song.

For your first real event, do not try to use every feature. Follow this order, test with one phone, and activate only the interactions that fit the room.

Sign In→Create Event→Event DNA→Guest Hub→Share QR / Link→Test Guest→Run Live
1

Sign in to the DJ host platform

Open Cue the Crowd and sign in with your authorized company DJ email and password.

Why: the host side is licensed software. Guests never use this login.
2

Click + CREATE NEW EVENT

Choose the event type: Wedding, Birthday, Class Reunion, Corporate Event, Holiday Party, School Event, Bar / Venue or General Event.

Why: every guest link, saved setting, live interaction and show belongs to a specific event.
3

Complete Event DNA and save

Add the event name and the details available for that event type. Weddings include partner names, date, guest count, age range, music style, couple story and topics to avoid.

Why: Event DNA gives the show-building tools context so the experience can feel specific to that event instead of generic.
4

Choose your operating style

If you want a planned sequence, open Show Builder. If you mainly want guest interaction—polls, requests, photos, buzzer, prize draw, announcements—go directly to Guest Hub.

Why: Cue the Crowd can run as a planned show or as an on-demand live toolkit. You do not need both at every event.
5

Open Guest Hub before guests arrive

Guest Hub is your live guest-control center. Confirm the correct event, then copy the Guest Join link or use the event QR workflow.

Why: one wrong event link means guests could connect to the wrong event. Check it before the room fills.
6

Connect one test phone

Open the Guest Join link on a separate phone/browser. Verify that the phone shows the correct event and that Guests Connected increases on the host side.

Why: this confirms the real guest path and Firebase live connection before you ask 150 people to scan.
7

Activate only the features you want

Use Guest Hub to turn on Voting, Predictions, Song Requests, Photos, Shoutouts, Buzzer, Tipping and other guest-facing tools as appropriate.

Why: the guest experience stays cleaner when people only see what is relevant right now.
8

Prepare Audience Display if the venue has a screen

Open Audience Display in a separate browser/window and move that window to the projector or venue TV. Keep the host controls on your DJ laptop.

Why: guests see a polished presentation while your private controls remain private.
9

Invite the room to scan once

Display the QR code on the venue screen, table card, wedding signage or another visible place. You can also send the Guest Join link digitally. Tell guests to keep the page open.

Why: they do not rescan for each activity. Their Guest Hub changes as you activate experiences.
10

Run the room

Use Guest Tools for polls, predictions, requests, photos, buzzer and tipping. Use Live Experience for prize draws, guest announcements, audience results, word cloud and Crowd Light Show. Use Show Builder/Host Control when you want a planned entertainment sequence.

11

Close and reset at the end

Close submissions you no longer want, stop light effects, clear live results and reset any activity that should not remain active.

Why: the event ends in a clean state and you do not accidentally leave guest interactions open.
Best first-event setup: start with 3–5 features, such as Voting, Song Requests, Photos, Buzzer and one Live Experience. Add more after you know how the room responds.

Song Requests + Priority Requests

Request PromptControls the instruction guests see when requests are open.
OPEN / CLOSE REQUESTSStarts or stops new guest song requests.
Smart QueueSimilar requests combine so you see actual demand instead of duplicate clutter.
MARK PLAYEDMarks a request as played.
DECLINEDeclines a request you do not want to use.
Priority BoostGuests can choose a paid boost amount after submitting a request. A boost raises priority; it never guarantees that you will play the song.
PAYMENT UNVERIFIEDThe guest submitted a Priority Request, but you have not yet verified the money in your payment account.
VERIFY + PRIORITIZEUse only after you confirm payment. It marks the Priority Request verified and raises it in the queue.

Shoutouts

TROUBLESHOOTING

Fast answers during an event.

A guest scanned the QR but nothing useful appears.

First confirm you are running the correct event in Guest Hub and that the join link/QR belongs to that event. Then confirm the feature you expect the guest to use is activated.

The Guests Connected number is not changing.

Test with a separate browser or phone using the real Guest Join link. Refresh Guest Hub if necessary. Do not test the host and guest path in the exact same browser session if you are trying to confirm independent attendance.

Guests can’t submit song requests/photos.

Confirm the feature is turned on and that submissions are currently open. Song Requests and Photos can be closed independently even while other guest features remain available.

A Priority Request says payment unverified.

That is intentional. Check your own payment account. Only click VERIFY + PRIORITIZE after you confirm the payment actually arrived.

I don’t want the venue to see my controls.

Use Audience Display in a separate browser/window on the projector or venue TV. Keep the host application on your private DJ screen.

I’m not sure what activity to run next.

Use Quick Launch for a known instant activity or Show Director when you want Cue the Crowd to recommend something based on time and room condition.
